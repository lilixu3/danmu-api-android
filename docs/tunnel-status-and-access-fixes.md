# Root 穿透状态与访问诊断修复（2026-10-04）

## 已修复

- HTTP 入口对确切的 `/.well-known/security.txt` 返回 404，不送入核心的 TOKEN 校验。
  其他未知路径及 API 继续执行原有鉴权；没有关闭 TOKEN 校验。
- Root 开机、App 手动启动及接管使用同一状态发布逻辑。原子写入状态 JSON，
  并保存 PID、进程启动 ticks、boot ID、启动实例 ID，归属应用 UID。
- Root 日志组件从 frpc 输出中接收注册成功、重连、冲突和失败事件，原子保存
  `link-state.json`。普通模式在日志泵中保存同样的连接快照。
- UI 只采信与当前进程身份匹配的连接证据，不再从最后 60 行日志重新猜测状态。
  清空和轮转日志不清除连接证据；新实例没有注册成功证据时保持未知。
- 手动“检测访问”比较本机/公网的健康入口、核心配置和完整页面下载。
  大页面按“公网 → 本机 → 公网复测”顺序采样，以保留直接访问前后的速度差异；
  健康实例核验仍需要本机小响应，无法保证检测对所有瞬态状态完全无影响。
  检查公网与本机实例一致后才发送用户 API Token。检测不跟随重定向、不自动重启，
  每个请求限时 5 秒。结果和重连前后 PID 写入诊断日志，不写 URL、Token、密码或响应正文。

## 更新生效

安装含本修复的 App 后，在 Root 模式重新连接一次穿透，会更新已安装的 Root 开机脚本，
并启动支持连接事件快照的日志组件。升级前仍在运行的旧实例没有这种证据，不能直接
从历史成功日志恢复为“已连接”。本次开发仅修改项目和本地构建资产，没有安装 APK、
替换手机已安装模块、修改实际穿透配置或启停正在使用的服务。

## 大响应变慢故障的现场证据

用户确认：本机和局域网正常；穿透的搜索、分集详情与少量弹幕正常，大量弹幕超时，
页面加载慢。重启 frpc 或 App 无效，另一 App 使用相同远端配置接入后再切回来可恢复。

2026-10-04 晚间在故障现场只读检测：

- 本机约 495 KB 的页面约 0.07 秒完成；公网相同页面约 3.3 秒完成。
- 公网健康入口和约 50 KB 的配置响应单次约 0.1 秒，健康信息与本机 PID 一致。
- 并发传输时页面约 12–15 秒，配置响应也增加到约 3–5 秒。
- 独立 VPS 请求同一公网入口，页面约 2.95 秒，健康入口约 0.07 秒。
- frpc 日志有本轮注册成功，无同名冲突；现场只有一份当前 App 的 frpc 和日志组件。
- 两份实际配置远端服务器与鉴权相同，加密和压缩均开启。当前 App 后端为
  `127.0.0.1`，另一 Flutter App 后端为 `127.0.0.2`。
- 两份已安装内核都打印 0.71.0，但构建信息不同：当前 App 是官方 Go 1.25.12
  产物；Flutter App 是 Go 1.27.1 的重建产物。版本号相同不能证明二进制相同。

后续只读复测出现恢复：frpc 仍是同一 PID 10262，最新注册记录仍为本轮启动的
2026-10-04 13:40:03 UTC（北京时间 21:40:03），未观察到新的自动重连记录。
单次页面约 0.46 秒，四份页面并发约 0.27–0.58 秒；开发侧没有修改配置或重启服务。
这说明其他 App 重新接入不是此次恢复的已证明必要条件，也不能把两次现象的先后
顺序直接当作因果。恢复后的参数对比不能替代故障现场的对比。

用户随后补充，此次恢复前只做了“打开当前 App → 复制首页 IPv4 地址 → 浏览器访问”。
这两个动作尚未分开测试，不能把恢复归因于其中任何一项。代码审计表明：MainActivity
进入前台会主动刷新运行状态；Root 恢复流程读取本机健康入口并恢复进程控制标记，
不会在这条恢复路径中重启 frpc；前台依赖预热仅适用于普通模式。网络监听回调更新
显示地址，未在这条路径中为 frpc 重新绑定网络。现场未记录到恢复前的完整系统状态，
不能据当前的 ACTIVE/Awake 状态推断故障期间没有系统限制。

后续复现应先保留仅经公网访问时的速度，再分开观察“仅打开 App”与“访问 IPv4 页面”
各阶段变化，同时记录进程和注册日志；重复对比仍需考虑经过时间及请求本身的影响。

证据已把问题收窄到穿透的大响应传输，尚未证明是压缩、复用、客户端构建差异或
远端会话处理中的哪一项。不能把状态显示修复当成大响应超时的修复，也不能因
另一客户端连接后恢复就排除所有 frps 会话相关行为。下一步应在保留原始配置和
现场测量的前提下，逐项进行受控对比，先只切换代理压缩开关，加密及鉴权保持不变。
实际配置修改与重启会短暂中断公网入口，必须按用户 AGENTS.md 的规则先确认。
故障未复现时不急于改参数，优先保留原配置及下一次故障的现场。

- HTTP 宿主集成测试覆盖 Worker/direct、GET/HEAD、合法 API 与错误 TOKEN。
- Root shell 测试实际执行共享发布函数，覆盖旧状态替换、可靠实例接管及 PID 重用。
- Android 日志 FIFO 集成测试使用重建的真实组件，验证 EOF、锁释放、日志上限和快照。
- Go 测试覆盖分片事件、重连、冲突、新实例、日志轮转及清空。
- 访问检测测试覆盖大页面、错误公网实例不发送凭据、本机/公网核心差异。
- 69 项相关 JVM 测试、27 项 Node 测试与 Go 测试通过，3 个 ABI 的组件输入校验通过。
- Debug APK 的 3 个 ABI 产物构建通过；未安装或发布。
- 真实手机重启及故障状态下的参数对比尚未执行；需要安装修复产物及明确授权。
