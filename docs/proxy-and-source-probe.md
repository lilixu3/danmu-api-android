# 代理与来源探测

入口位于「设置 → 网络设置」，仅管理弹幕来源的线路与代理节点。「下载与更新」单独位于网络设置下方、GitHub Token 上方，管理 GitHub 连接方式、下载镜像、连通检测和核心自动检查间隔。工具页「排查与追踪」的顺序为：运行日志、来源探测、运行诊断。

## 节点与分流

- HTTP、HTTPS、SOCKS5 支持地址、端口以及可选的用户名和密码。HTTP/HTTPS 代理访问普通 HTTP 目标时使用完整 URL 转发，访问 HTTPS 目标时使用 CONNECT；SOCKS5 将目标域名交给代理解析。
- 页面以来源线路为主体，代理节点在相邻标签页管理。点击来源展开连接路径，再选择默认线路、增强直连或一个代理节点。巴哈姆特、TMDB、哔哩哔哩、Animeko、爱壹帆接入了核心代理，默认项显示「沿用核心配置」；其余弹幕源显示「使用设备当前网络」。GitHub 的线路已移至「下载与更新」，保留增强直连、App 节点及原有下载镜像，打开页面不会覆盖已保存的节点绑定。
- 每个来源只保留一个明确的线路选择，不需要另开代理或增强直连总开关。保存后，新请求按这一条规则执行；明确选择 App 节点或增强直连时，覆盖该来源的核心代理改写。
- 升级时迁移已移除的「普通直连」规则为「沿用核心配置」，保留已有节点、认证信息和来源绑定；不为未配置的来源写入默认规则。旧版已启用的增强直连来源保持选中；没有单独修改的来源保留原线路、协议、DoH 和超时。旧版核心代理或 GitHub 下载镜像仍按原配置显示，直到用户明确更换该来源线路。
- 选择「沿用核心配置」恢复该来源的核心 `PROXY_URL` 规则，未配置核心代理时使用设备当前网络，并优先于旧版 App 默认节点规则。明确选择的 App 代理节点优先级最高，节点失效或认证失败会报告错误，不自动回退到核心代理或设备网络。
- App 的核心 HTTP/HTTPS 中转支持带用户名密码的地址、尾部 `/` 和逗号分隔配置；认证中的 `@` 不作为反代标记。配置热更新时按需启停本地代理服务。来源探测复用当前运行核心的 `makeProxyUrl()`，不另行模拟 `PROXY_URL` 规则；旧核心忽略的配置不会被探测标为已使用。Worker 模式在当前 Worker 中解析和探测，切换核心时重新绑定。核心能力或返回格式无法识别时显示「未确认」，不请求猜测的代理地址。
- 「增强直连」只对已经适配的来源提供。爱壹帆可配置代理，但不因此宣称支持增强直连或保证解除地区限制。
- 来源列表从当前核心的 `SOURCE_ORDER` 配置目录加载；未启用的来源也能预设线路。修改线路不改变来源启用状态。
- 自定义源依赖核心传递来源上下文；当前核心的 `sourceLogContext` 会在 App 适配层中复用。不同核心版本如未提供上下文，部分独立规则需要额外适配，不能仅凭界面已选择宣称该核心已适配。
- GitHub 使用 Android 网络层，支持独立线路，在 Node 服务未启动时也可更新、下载。GitHub 未设置独立规则时沿用其原有线路选择。

## 原生节点与升级迁移

仅支持 HTTP、HTTPS 和 SOCKS5，可手动输入，或每行粘贴一个节点链接。
支持其他客户端提供的本机 HTTP/SOCKS5 端口。HTTPS 以及显式开启 TLS 的 SOCKS5
可设置服务器名称；只有用户明确配置时跳过代理服务器证书验证，目标 HTTPS 的证书
验证始终保留。

已移除订阅地址、更新功能、远程 provider、订阅解析依赖和内置 Mihomo。
升级时清除旧订阅数据，保留可原生处理的节点与 ID；旧的扩展协议节点移除后，其来源
规则仍指向原 ID，显示节点失效，直到用户更换。不能因为一条旧节点不受支持就丢掉整份
网络配置，或把该来源自动改成直连。

网络页通过服务在启动时固定的脚本指纹对照 APK 资产。`app-runtime-assets.json` 统一列出全部宿主运行脚本，提取检查和两侧指纹共用此清单，包含原生增强直连、DNS、Worker 和刷新包装。旧 Root 进程没有指纹或不匹配
时提示用户在首页停止后重新启动服务；仅安装 APK 或重开界面不代表独立 Root 服务
已经更新。打开网络页不会擅自重启现有服务。正常启动仍由 NodeProjectManager 提取
当前 APK 的托管脚本，RootRuntimeController 再增量同步到 Root 工作目录。

代理出站承载 HTTP/1.1；增强直连继续保留原有 H2/H3 策略。沿用核心配置时的设备网络和代理服务器自身
的连接都可能经过用户开启的系统 VPN，因此只有接口访问成功不足以证明来源节点已生效。

## 来源探测

默认只显示当前配置已启用的来源。顶部「来源探测」标题右侧的设置按钮可以切换「显示全部来源」和「只显示启用」，独立保存显示偏好，不修改核心的来源启用状态。批量探测覆盖所选范围；切换范围保留已有结果，刷新目录会清除旧结果。支持批量、单项重测和取消，最多三个来源并行。

网络设置的「显示全部」左侧提供「连通性检测」，检测当前列表中的来源，沿用已保存的实际线路。来源名称右侧以绿色显示响应耗时、红色显示「未连通」。GitHub 在独立的「下载与更新」页面使用 Android 当前线路检测；本地来源显示「无需联网」。源站返回 HTTP 401/403 等仍表示网络可达，具体业务限制可到来源探测查看。

线路选择弹窗的「添加节点」左侧提供节点批量连通性检测，检测当前节点列表，最多三个并行，支持取消。使用节点的代理认证和 TLS 参数实际请求 Cloudflare HTTPS 204 测试接口，不保存或切换来源线路；结果显示在节点名右侧，并与代理节点页共享。该延迟是完整 HTTPS 请求耗时，不能代替目标来源的可达性测试。修改线路或节点配置会丢弃相关旧检测结果，取消操作不会写入失败状态。

来源探测页按本次界面要求将「已响应」和「未响应」都显示为绿色，用文字区分结果；接口受限仍保留单独状态。网络设置页失败则显示红色「未连通」。

探测结果包含延迟、线路、出口地区参考、HTTP 限制原因和测试时间。沿用核心配置、App 代理节点、核心代理/反代、App 增强直连分别标注。系统 VPN 和 HTTP 代理仅报告系统可观察到的信号，不能由公网 IP 推断具体代理软件。

爱壹帆优先从当前已加载模块的接口声明和导出常量识别详情地址，不固定旧 API 域名，也不创建额外的来源实例。直接加载模式中磁盘文件更新但模块仍在内存时，继续探测实际运行的接口。新核心改为无法识别的接口声明时显示「未确认」；该结果不表示源站离线，也不保证搜索、签名与弹幕链路全部可用。

地区不再查询第三方 IP 网站，也不跨来源复用出口地区。对于返回 Cloudflare 标识的目标，沿用同一来源和线路访问该域名的 `/cdn-cgi/trace`；只接受未重定向、体积受限、域名与 IP 格式正确的响应，并读取 `loc`，不把 `colo`（机房位置）作为出口地区。

界面将结果标为「同域检测」，显示被测域名和时间。这是该域名本次诊断连接的出口 IP 归属地，不能保证其他业务域名、按路径/IP 分流、不同地址族或后续连接的出口相同。无诊断能力、反代、超时或无效响应一律显示「未确认」，不把节点名称或第三方查询推测成真实地区。

TMDB 探测读取配置管理保存的 `TMDB_API_KEY`，与核心一致通过 `api_key` 查询参数请求；沿用核心配置、节点代理、增强直连和核心代理都使用同一配置。Key 不出现在探测返回结果或同域出口诊断请求中。未配置 Key 时，TMDB 的 HTTP 401 显示「已响应 · API Key 未配置」，计入已响应；已配置 Key 仍返回 401 则标为接口受限，详情提示 Key 无效或无权限。配置通过现有共享配置热更新，清空 Key 后再次探测会恢复缺失提示。

自定义、第三方和 VOD 来源缺少地址时，不发送请求，来源探测和网络设置都显示「未配置」，不计入连接失败。保留核心内置默认地址，但尊重显式清空；VOD 同时支持 `名称@URL` 和裸 URL。来源探测新增「未配置」筛选。TMDB 缺少 Key 但网络本身超时，仍按实际连接失败处理。

其他 HTTP 401、403、429 等代表网络收到响应，标记为接口受限并说明原因，不等同于无法建立连接。本地弹幕标记为本机，无需联网。部分来源仅做站点/接口可达性探测，不承诺搜索、详情和弹幕接口全部可用。新来源自动显示；找不到可探测地址时明确显示暂不支持。
