# GitHub 匿名配额保护

- 未配置 Token 且已知匿名 core 配额耗尽时，暂停前台 App / 核心自动检查以及核心工作区的自动远端刷新，不改动用户设置的检查间隔。
- 手动检查、安装、重装、回退、分支、PR 和其他 GitHub API 请求统一拦截。普通界面提示可直接进入 Token 设置；兼容模式可直接验证并保存 Token。
- 配额来自已有账号快照、免费的 `/rate_limit` 查询和官方 API 响应头。代理服务器的响应头不覆盖官方账号配额；不会为每个请求额外查询配额。
- 当前请求成功且剩余次数刚好为零时保留成功结果，仅拦截后续请求。首次遭遇额度耗尽后不再执行候选线路或重试循环。
- 按 GitHub 返回的重置时间放行，提示使用剩余分钟数；缺少有效重置时间时使用 60 秒的有限退避，避免永久锁死。已过期的持久快照不会重新触发退避。
- Token 存在时不套用匿名限制，输入新 Token 的验证请求也不受匿名额度影响。未知额度、权限错误、网络故障均不当作额度耗尽。
- search 额度单独记录，其耗尽不影响 core 更新检查。
- 不拦截播放器接口、本地弹幕操作、服务启动/停止、删除本地核心、本地依赖修复、已下载 APK 安装、GitHub 网页、raw/codeload 或已知下载地址。
- 配额提示可关闭，不自动重放安装/回退等用户操作；恢复后由用户重试。自动检查在后续正常前台触发时恢复。

测试：`GithubQuotaTrackerTest`、`GithubQuotaInterceptorTest`。
