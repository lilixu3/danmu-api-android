# 工程硬标准（违反即返工）

本文件对所有贡献者（含 AI 代理）生效。以下条目是硬性要求，不是建议。

## 1. 禁止兜底掩盖故障

- 任何修复都**必须先找到并消除根因**，禁止用"兜底默认值、降级路径、try-catch 吞异常、
  静默重试、占位实现"让症状消失。
- 判断标准：修完后，"导致问题的条件"再次出现时必须**仍然显式失败**，而不是被新代码掩盖。
- 示例（反例 → 正确做法）：
  - 图标加载失败就画一个兜底图标 → 正确：返回明确错误并写入日志，让资源缺失暴露。
  - 端口探测失败就随机换端口 → 正确：按配置优先级解析端口，占用时给出明确归属判断。
  - 后台线程异常吞掉继续跑 → 正确：转为显式失败状态并记录根因。

## 2. 先取证，后动手

- 修复前必须拿到可复现的证据（日志、退出码、堆栈、健康接口返回、注册表/进程实况），
  禁止凭猜测"试试看"。
- 环境性因素（防火墙、网络类型、杀软、权限）要逐项取证排除，不能一句话归因。

## 3. 修复必须可验证

- 每个修复都要有对应的验证手段（自动化测试或可复现命令），并记录实际执行结果。
- 修复提交里说明：根因是什么、为什么这样修、如何证明修好了。

## 4. 与既有实现对齐

- 与已有端（Android/iOS/Web）共享行为时，先读对方实现再动手，
  优先级、默认值、错误文案、语义保持一致；不确定就问，不要发明新规则。

## 5. 诊断信息不得静默丢弃

- 捕获异常时必须转为：失败状态 / 日志 / 返回给调用方的诊断值，三者之一。
- `runCatching {}` 只能用于"把异常转为显式失败"，禁止空处理。
